# Глубокое ревью бэкенда learn_kids

**Дата:** 2026-02-14  
**Область:** backend (Go, Gin, PostgreSQL, JWT, Gemini API)

---

## 1. Резюме

Бэкенд структурирован по доменам (users, lessons, progress, chat, comments), с чёткими интерфейсами репозиториев, централизованной конфигурацией и middleware. Безопасность в целом на хорошем уровне: rate limiting, CORS, лимит тела запроса, защита от timing attack при логине, системный промпт для чата формируется на сервере. Ниже — замечания по улучшению и уже внесённое исправление.

---

## 2. Внесённое исправление

### JWT: явная проверка алгоритма подписи

В `internal/domain/users/jwt.go` при разборе токена не ограничивался допустимый алгоритм. Для защиты от атак «alg: none» и подмены алгоритма добавлена опция:

```go
jwt.ParseWithClaims(..., jwt.WithValidMethods([]string{"HS256"}))
```

Рекомендация из документации golang-jwt: явно указывать список допустимых методов подписи.

## 3. Безопасность

### 3.1 Сильные стороны

- **Auth:** JWT в заголовке, при невалидном Bearer возвращается 401 (не пропуск анонима).
- **Пароли:** bcrypt, лимит 6–72 символа, защита от timing attack при логине (dummy bcrypt при отсутствии пользователя).
- **Роли:** проверка teacher через значение из контекста (без лишнего запроса в БД).
- **Чат:** системный промпт и история формируются на сервере; клиент передаёт только `message` и `lesson_id` — снижен риск prompt injection.
- **Лимиты:** тело запроса до 1 MB; длина сообщения чата и комментария ограничены.
- **Trusted proxies:** заданы для корректного определения ClientIP (rate limit, логи).
- **Миграции:** используются параметризованные запросы; в репозиториях — только плейсхолдеры `$1, $2...`, SQL injection по коду не обнаружен.

### 3.2 Рекомендации

- **Rate limiter:** реализация in-memory. При нескольких инстансах лимиты будут считаться по каждому инстансу отдельно. Для продакшена с горизонтальным масштабированием рассмотреть общий store (например, Redis).
- **Логирование ошибок:** в `httplog.LogError(c, err)` не передаётся путь/метод запроса. Имеет смысл добавлять `method`, `path` (или `request_uri`) для удобства разбора в production.
- **Ошибки валидации в ответах:** в ряде мест при `ShouldBindJSON` в 400 возвращается `err.Error()` (например, `users/handler.go`, `lessons/handler.go`). Для части ошибок валидатора это может раскрывать внутренние детали. Безопаснее отдавать общее сообщение вида «invalid request body» или структурированные поля ошибок без стека/внутренних имён полей.

## 4. Архитектура и код

### 4.1 Плюсы

- Чёткое разделение: handler → repo (интерфейсы), тесты с моками (chat, users).
- Компиляционная проверка реализации репозиториев: `var _ Repository = (*Repo)(nil)` в lessons, users, progress, comments, chat.
- Конфигурация через env, проверка `JWT_SECRET` в production.
- Graceful shutdown с таймаутом 10 с.
- Таймауты HTTP: Read 15 с, Write 90 с (под вызовы Gemini), Idle 120 с.
- Health check проверяет БД (503 при недоступности).

### 4.2 Замечания

- **main.go:** константа `defaultSystemPrompt` и строка в `lessonContextFn` дублируют текст. Имеет смысл вынести в одну константу или функцию.
- **Комментарии к уроку:** при создании комментария к несуществующему уроку БД вернёт ошибку FK (23503). Сейчас это приводит к 500. Можно обрабатывать 23503 и отдавать 404 «lesson not found» для единообразия с остальным API.
- **Progress:** при `SetLessonProgress` для несуществующего урока БД также отреагирует FK. Аналогично — при желании можно маппить в 404.
- **CORS:** если позже понадобится отправка cookies/credentials, нужно будет задать `Access-Control-Allow-Credentials: true` и не использовать `*` в `Access-Control-Allow-Origin` (сейчас используется один origin из конфига — это ок).

## 5. База данных

- Миграции через `golang-migrate`, встроенные в бинарь (embed).
- В `db.RunMigrations` используется `database/sql` + драйвер `postgres` (lib/pq), тогда как приложение работает через pgx. Для миграций это допустимо; оба понимают один и тот же URL.
- Пул: MaxConns=20, MinConns=2, MaxConnLifetime=1h, MaxConnIdleTime=30m — разумные значения.
- В репозиториях запросы параметризованы; динамическая сборка в `lessons/repo.UpdateLesson` (поля `title`, `description`) делается через плейсхолдеры `$N` и слайс `args`, не конкатенация строк от пользователя — безопасно.

  - Добавить интеграционный кейс: запрос с невалидным/истёкшим JWT → 401.
  - Проверка teacher-only маршрутов без роли teacher → 403.
  - При необходимости — тест на отклонение JWT с `alg: none` (при наличии публичного парсера в тестах).
