# Домен: Чат с Gemini (история диалогов по урокам)

**Обновлено:** 2026-02-14

## Назначение

Чат с ИИ-помощником по уроку (Gemini). История сохраняется по пользователю и уроку. Пользователь может очистить свою историю чата.

## Контракт API

- `POST /api/v1/chat` — отправить сообщение в Gemini. Тело: `{ "lesson_id": "uuid", "message": "текст" }`. Ответ: `{ "text" }`. Auth: JWT. Rate limit: 20/мин на IP.
- `GET /api/v1/chat/:lessonId/history` — история чата текущего пользователя по уроку. Ответ: `{ "messages": [{ "role", "text" }] }`. Auth: JWT.
- `DELETE /api/v1/chat/:lessonId/history` — очистить историю чата по уроку. Ответ: 204 No Content. Auth: JWT.

**ВАЖНО:**
- Клиент отправляет только `message` (строка) — последнее сообщение пользователя. Историю сервер загружает из БД самостоятельно.
- Поле `messages` (массив) **удалено** из запроса — клиент больше не может подменить контекст диалога.
- System prompt формируется на сервере по `lesson_id` для защиты от prompt injection.
- Лимит на сообщение: 1000 символов.
- Лимит истории: 50 сообщений (загружаются последние N из БД).

## Архитектура

- Handler принимает интерфейс `Repository` (не конкретный `*Repo`), что позволяет подменять репозиторий в unit-тестах.
- `APIBaseURL` и `HTTPClient` — публичные поля Handler, переопределяемые в тестах для мока Gemini API.
- Логирование через `log/slog` (structured JSON logging).

## Связи

- История хранится в таблице `chat_messages` (user_id, lesson_id, role, text, created_at).
- Привязана к уроку и пользователю.
- Системный промпт строится из title/description урока через `LessonContextFunc` (инжектируется в chat handler при старте).

## Безопасность

- **Prompt injection protection:** клиент отправляет только `message`; полная история загружается из БД (server-authoritative). System prompt формируется на сервере.
- API-ключ Gemini передаётся через заголовок `x-goog-api-key` (не через URL query parameter).
- Ответ Gemini ограничен 2 MB (`io.LimitReader`) для защиты от OOM.
- HTTP-сервер настроен с таймаутами (`ReadTimeout: 15s`, `WriteTimeout: 90s`, `IdleTimeout: 120s`).
- `SetTrustedProxies` настроен для корректного определения клиентского IP.

## Тестирование

- Unit-тесты: `chat/handler_test.go` — 11 тестов покрывающих валидацию, загрузку истории из БД, мок Gemini API.
- Тесты используют `mockChatRepo` (имплементирует `Repository`) и `httptest.NewServer` для мока Gemini.

## Фронтенд

- Компонент `LessonChat` принимает только `lessonId` (не весь объект урока).
- Клиент отправляет `{ lesson_id, message }` — system prompt и историю **не** формирует.
- История загружается через `GET /chat/:lessonId/history` при открытии урока (если пользователь авторизован).
- При ошибке 429 (rate limit) показывается понятное сообщение на русском.
- Сообщения чата выводятся как обычный текст (экранирование React); лимит 1000 символов проверяется на фронте (maxLength, validateChatMessage). При появлении рендера markdown/HTML в чате потребуется санитизация или экранирование.

## Решения

- Роль сообщения: `user` | `model`.
- История загружается при открытии урока (если пользователь авторизован).
- Сохранение: при отправке сохраняем сообщение пользователя, затем загружаем историю из БД, затем отправляем в Gemini, затем сохраняем ответ модели. Ошибки сохранения логируются (WARN), но не блокируют ответ.
- Rate limit: 20 запросов в минуту на IP.
