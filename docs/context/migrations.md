# Миграции БД

**Обновлено:** 2026-02-27

## Назначение

SQL-миграции применяются при старте API (golang-migrate). Проект рассчитан на **первый запуск** без существующей БД: схема и предопределённые курсы заложены в миграциях.

## Структура (после консолидации)

| Миграция | Содержимое |
|----------|------------|
| `000001_init` | Вся схема: таблицы (users, user_roles, modules, lessons, lesson_steps, lesson_materials, lesson_tags, checklist_items, user_lesson_progress, user_checklist_progress, lesson_comments, chat_messages, lesson_reactions, comment_reactions), enum (user_role, lesson_type, material_kind, progress_status), индексы. Роли: источник истины — `user_roles`; `users.role` nullable. `material_kind`: link, file, simulator. |
| `000002_seed_admin` | Предопределённый пользователь-администратор (логин admin, пароль admin12, смена при первом входе). |
| `000003_predefined_course_pico` | Модуль «Робототехника с нуля: Raspberry Pi Pico», уроки 0–14 (включая Wokwi, кнопка/светодиод, ШИМ, серво, светофор, HC-SR04, температура, ночник и расширенные шаги). |
| `000004_predefined_course_robot_wheels` | Модуль «Робот на колёсах», уроки 1–4 (что понадобится, подключение драйвера, вперёд/назад, повороты). |
| `000005_predefined_course_smart_home` | Модуль «Умный дом на Pico W», уроки 1–10 (WiFi, веб-сервер, датчики, ночник, сигнализация, умная комната, презентация). |

## Правила

- **Предопределённые курсы** остаются в **отдельных миграциях** (000003, 000004, 000005), чтобы контент курсов можно было править и откатывать по модулям.
- В материалах уроков используется только `material_kind`: `link`, `file`, `simulator` (тип `mermaid` удалён).
- Откат (down) для курсов удаляет только данные своего модуля и уроков, не трогая схему и других пользователей.
